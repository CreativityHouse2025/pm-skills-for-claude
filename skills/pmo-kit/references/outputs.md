# Outputs

Structures for each thing this skill produces.

## Template set

One template per required document for a given project size.

Each template has:
- Header: organisation name as provided, document title, project ID in the organisation's format, version, date, author
- The core sections from the catalog for that document
- A guidance note under each section heading, marked `[Guidance: ... delete before issuing]`, saying what a good entry contains and giving one short example
- The organisation's own scales, colour definitions and terms where the document uses them
- An approval block showing the approver for that project size from the standards sheet
- A version history table

Deliver an index first: which templates exist for Small, Medium and Large, and which rules are still `SUGGESTED`.

## Compliance check

1. **Result** in one line: follows the standard, follows it with gaps, or does not follow it.
2. **Against the organisation's standard**: table of rule, what the document shows, pass or gap, and the fix. Cover the right template for the project size, required sections, approvals, ID and version format, and the scales and colours used.
3. **Against good practice**: the most important points from the review checklist for that document, kept separate.
4. **What to fix first.**

If a rule the document breaks is still `SUGGESTED`, say so: the document cannot fail a rule that has not been agreed.

## Portfolio status report

1. **Header**: period covered, date prepared, number of projects, how many reports were received, stale or missing.
2. **Needs a decision**: projects requiring leadership action, each with the decision needed, by when, and the consequence of waiting.
3. **Summary counts**: projects by colour (rule-based), total approved budget, total spent, overall variance, each shown with its calculation.
4. **Project table**: ID; project; size; owner; colour by rule; colour as reported (if different); schedule status against the next milestone; budget against spend; top risk or issue; report date.
5. **Across the portfolio**: risks that appear in more than one project, shared people or suppliers that several projects depend on, milestones in the next period.
6. **Data gaps**: what is `Not reported`, which reports are stale, and who to ask.

Keep it to what a leadership meeting can read in a few minutes. Detail belongs in each project's own report.

## Intake form and prioritisation

**Intake form**: requester; problem or opportunity; proposed result; expected benefit and how it would be measured; rough cost and duration; urgency and its reason; what happens if it is not done; dependencies; sponsor.

**Scoring model**
- Four to six criteria agreed by the organisation (for example strategic fit, benefit, urgency, cost, risk, effort)
- A weight per criterion, totalling 100
- A defined rating scale with a description for each level, so two people rate the same way
- Table: project; rating per criterion (supplied by the organisation); weighted score; rank
- The working for each score
- A note on what the numbers do not capture, and a reminder that the ranking informs the decision

## Stage gates

For each gate: name; when it happens; what must exist (documents by ID); what must be true (criteria); who decides; possible outcomes (go, go with conditions, hold, stop). Scale the number of gates to project size: small projects may have only a start and a close.

## Handbook ("How we run projects here")

Written for a project manager joining the organisation, generated from the standards sheet:
1. How projects are sized, and what that means for you
2. What you must produce, by size, with links or names of templates
3. Who approves what
4. The gates your project will pass
5. How and when to report, and what the colours mean
6. How to rate and escalate risks
7. Naming, numbering and where things are kept
8. Who to ask

Anything still `SUGGESTED` is shown as such.

## Lessons across projects

When given lessons learned from several projects: group them by theme, show how many projects raised each theme, and turn the recurring ones into a proposed change to the standards sheet (marked `SUGGESTED`).
