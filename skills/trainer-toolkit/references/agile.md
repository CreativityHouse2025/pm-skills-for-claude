# Agile and iterative deliverables

Use these when the fact sheet's approach is agile or hybrid, or when the person talks about sprints, backlogs or stories. In a hybrid project, combine them with the catalog: a charter and budget from the catalog, a backlog and sprint plan from here.

Items marked *needs data* are built only from numbers the person supplies. Without data, give the empty structure and say what to record each sprint.

| ID | Document | What it settles | Core sections | Format | Builds on | Tier |
|---|---|---|---|---|---|---|
| A-01 | Product vision and roadmap | Where the product is going and in what order | Vision statement; target users; goals; themes or releases over time; what each release delivers | Document | I-03 if one exists | core |
| A-02 | Product backlog | Everything that might be built, in priority order | ID; item (story or feature); value; priority; estimate; status | Sheet | A-01 | core |
| A-03 | User story with acceptance criteria | One piece of value from the user's point of view, and how to know it is done | "As a [user], I want [capability], so that [benefit]"; acceptance criteria as testable conditions; notes; estimate | Document or sheet row | A-02 | core |
| A-04 | Story map | How stories fit the user's journey and which come first | User activities across the top; stories under each activity; release slices as horizontal bands | Board or sheet | A-02 | standard |
| A-05 | Release plan | Which backlog items land in which release | Release goal; target date; included items; dependencies; risks | Sheet | A-02 | standard |
| A-06 | Sprint plan | What the team commits to this sprint | Sprint goal; dates; selected items; tasks and owners; capacity | Sheet | A-02 | core |
| A-07 | Kanban board setup | How work flows and where it gets stuck | Columns (for example To do, In progress, Review, Done); work-in-progress limits; card fields; rules for moving a card | Board or sheet | A-02 | standard |
| A-08 | Story point estimates | The relative size of backlog items | Item; estimate; the reference story used; reasoning for outliers | Sheet | A-02 | standard |
| A-09 | Definition of Done | The shared bar every item must clear | Checklist covering build, test, review, documentation and acceptance | Document | - | core |
| A-10 | Burndown chart *(needs data)* | Whether the sprint is on track | Days of the sprint; planned remaining work; actual remaining work | Chart | A-06 | standard |
| A-11 | Velocity chart *(needs data)* | How much the team reliably completes per sprint | Completed points for each recent sprint; average; trend | Chart | A-06 | standard |
| A-12 | Daily stand-up summary | What changed since yesterday and what is blocked | Per person: done, planned, blockers; actions on blockers | Document | A-06 | standard |
| A-13 | Sprint review summary | What was delivered and what stakeholders said | Sprint goal and outcome; items completed and not completed; feedback; backlog changes | Document | A-06 | standard |
| A-14 | Retrospective record | What the team will change next sprint | What went well; what did not; one to three improvement actions with owners | Document | A-06 | core |
